# word-engine Future Work

This document tracks known bugs, unimplemented features from the design spec, and params.yaml fields that are defined but not yet fully wired up.

---

## 1. Known Bugs

### 1.1 Cross-reference display not fully native
**Status:** Partial — REF field is inserted, but the displayed text may still appear as plain text in some scenarios before field update.

**Description:** `{{ref:fig-1}}` is rendered as a Word REF field (`{ REF fig_1 \h }`), but the two-pass pre-scan that populates the registry does not yet fully integrate with the SEQ bookmark naming. In some cases, the placeholder text shown before F9 update may not match the final resolved value.

**Affected:** `src/renderer/renderer.py`, `src/renderer/cross_reference.py`

**Expected fix:** Align ReferenceRegistry ID mapping with the bookmark names generated by `caption.py` SEQ fields. Ensure `fig_1` → `fig_1` bookmark pairing is consistent end-to-end.

## 2. Unimplemented Items from `word_engine_design_spec_v1.0.md`

### 2.1 Normalizer module (stub only)
**Status:** Stub — `src/normalizer/normalizer.py` only does pass-through.

**Design requirement:** The normalizer should apply low-risk automatic corrections:
- Trailing whitespace cleanup
- Excessive blank line reduction
- Full-width to half-width character conversion (contextual)
- Punctuation normalization for zh-TW
- Default param fallback injection

### 2.2 Image import from remote URLs
**Status:** Partial — local image paths work; remote URL download exists but may not be reliable.

**Design requirement:** `params.yaml` defines `images.download_remote_images: true` and `use_proxy_for_download: true`. The full implementation should:
- Download remote images with proxy support
- Cache downloaded images to avoid repeated network calls
- Handle timeouts and fallback gracefully

**Affected:** `src/renderer/renderer.py` → `_render_image()`

### 2.3 Nextcloud cloud sync (`syncer` module)
**Status:** Stub — `src/syncer/syncer.py` returns `{"status": "skipped"}`.

**Design requirement:** After export, the `syncer` should:
- Upload refine.md, params.yaml snapshot, docx, pdf, and render logs to Nextcloud
- Use WebDAV PUT with credentials from `NEXTCLOUD_CONFIG.md`
- Generate and return a shareable link
- Organize files under `project_document/{{project_id}}/`

### 2.4 QC checklist items not fully validated
**Status:** Partial — basic structural checks are in place, but the full checklist defined in the design spec is not implemented.

**Missing QC checks from spec:**
- `toc_exists` — verify TOC field is present if enabled
- `figure_numbering_consistent` — verify figure numbers are sequential
- `table_numbering_consistent` — verify table numbers are sequential
- `references_resolved` — verify all `{{ref:*}}` can be resolved
- `bibliography_style_correct` — verify bibliography section format
- `cross_references_resolved` — verify all REF field targets exist
- `no_broken_image_links` — verify all image paths are accessible
- `font_consistency_checked` — verify specified fonts are available
- `page_breaks_checked` — verify page break placement

## 3. Params Schema Features Not Yet Implemented

The following parameters are defined in `configs/params.schema.v1.0.yaml` but are not yet read and applied by the renderer.

### 3.1 Heading styles (all levels)
`headings.level_1` through `level_6` define:
- `font_family`, `font_size_pt`, `color`, `bold`, `italic`, `underline`
- `alignment`, `line_spacing`, `space_before_pt`, `space_after_pt`
- `indent_left_cm`, `first_line_indent_cm`
- `keep_with_next`, `keep_together`, `page_break_before`

**Current behavior:** Renderer applies only basic bold + fixed font size for H1-H3. Params are not read.

### 3.2 Paragraph styles (body_1 through body_6)
`paragraphs.body_1` through `body_6_compact` define:
- Font family (east_asia + latin), font size, color
- Alignment (justify/left/right), line spacing
- First-line indent (`first_line_indent_cm`)
- Space before/after

**Current behavior:** Renderer uses python-docx default Normal style. Params not applied.

### 3.3 List styles
`lists.bullet` and `lists.numbered` define:
- Font family/size, bullet/number styles per nesting level
- Indentation (`indent_left_cm`, `first_line_indent_cm`)

**Current behavior:** Renderer uses python-docx built-in List Bullet/Number styles.

### 3.4 Caption styles
`captions.figure_caption` and `table_caption` define:
- Font family, size, color, alignment, spacing

**Current behavior:** Renderer adds basic 10.5pt italic runs but does not read caption style params.

### 3.5 Header and footer
`header_footer` section defines:
- `header_text_left/center/right`, `footer_text_left/center/right`
- Page number style, start page
- Template variables: `{{document_title}}`, `{{project_id}}`, `{{page}}`, `{{pages}}`

**Current behavior:** Not implemented. Headers/footers are absent in current output.

### 3.6 Cover page: logo and extra fields
`cover.logo_path`, `cover.logo_width_cm`, `cover.extra_fields`
- Logo image insertion on cover page
- Arbitrary extra key-value fields

**Current behavior:** Logo and extra fields are ignored.

### 3.7 Cover page: reviewer / approver fields
`cover.show_reviewer`, `cover.show_approver`
- Reviewer and approver name display on cover

**Current behavior:** These fields are parsed but `project.reviewer` and `project.approver` values are not displayed.

### 3.8 Table of Contents: list of figures / list of tables
`list_of_figures`, `list_of_tables` sections define:
- Whether to generate separate lists
- Title, right-align page numbers, hyperlinks

**Current behavior:** Not implemented. Only main TOC is generated.

### 3.9 Image parameters
Several `images` params are defined but not applied:
- `space_before_pt`, `space_after_pt` — paragraph spacing around images
- `keep_aspect_ratio` — aspect ratio enforcement
- `alt_text_from_filename` — auto-populate alt text
- `source_note_enabled` / `source_note_prefix` — image source attribution
- `placement_rule` — nearest paragraph placement
- `wrap_style` — inline vs floating

### 3.10 Table parameters
Several `tables` params not yet applied:
- `width_mode` — auto_fit / fixed
- `cell_padding_pt`, `border_color`, `border_width_pt`
- `allow_row_break_across_pages`
- `first_row_bg_color` — header row background
- `repeat_header_row` — repeat header on page break

### 3.11 Numbering styles
`numbering.heading_numbering_enabled` and `heading_formats` define:
- Auto-numbering for headings (e.g., `1.2.3`)
- Decimal / Roman numeral styles

**Current behavior:** Headings are not auto-numbered.

### 3.12 Appendix, footnotes, equations
These sections are defined in the schema:
- `appendix` — alphabetic appendix numbering
- `footnotes` — footnote style and restart per section
- `equations` — equation numbering (flat / chapter modes)

**Current behavior:** None of these are implemented.

### 3.13 Bibliography / references
`references` section defines IEEE/APA bibliography rendering.
**Current behavior:** Not implemented. No bibliography support.

### 3.14 Colors section
`colors` defines semantic color tokens (text_primary, accent_primary, etc.) that should be applied throughout the document.
**Current behavior:** Color values are validated but not applied to rendered content.

## 4. Architecture / Process Items

### 4.1 Multi-round revision workflow
The design spec envisions multiple review rounds with the normalizer and QC feeding back to the document author. Currently the review loop is one-directional (render → check → mark-reviewed) without a structured feedback path for automated re-editing.

### 4.2 PR review and merge workflow
Currently all commits go to `develop` branch. A proper release flow should:
- Create a `main` branch for stable releases
- Require PR review before merge to main
- Tag releases with semantic versioning

### 4.3 Word SEQ / REF field STYLEREF for true chapter numbering
The current chapter-mode caption uses `Figure_Ch1`, `Figure_Ch2` etc. as separate SEQ sequences. True chapter-aware numbering requires `{ STYLEREF 1 \n }-{ SEQ Figure \* ARABIC }` which relies on Word heading styles being correctly mapped. This is deferred to a future phase.
